# 선택형 개인·연구 관리 기능 추가

## 목적

새 사용자가 실제로 요청할 때만 개인 일정·아이디어와 연구 문서·실험 결과 관리 기능을 설계한다.
현재 `personal/`과 `research/`는 확장 지점만 제공하며 관리 기능은 구현하지 않는다.

## 착수 조건

- [ ] 사용자가 실제 사용 사례를 요청했다.
- [ ] 요청이 개인 관리와 연구 관리 중 어디에 해당하는지 확인했다.
- [ ] 저장할 데이터의 공개·비공개 경계를 정했다.
- [ ] 구현 전 별도 Spec을 승인했다.

## 후보 범위

### 개인 관리

- 일정·미팅·할 일 관리
- 아이디어 저장·검색
- 선택적 일일 기록
- 입력 포맷과 생성 명령
- 개인정보의 Git 추적 여부

### 연구 관리

- 프로젝트별 연구 문서 구조
- 실험 계획·설정·결과 기록
- 정본 문서와 실행 로그 분리
- 파일 네이밍·템플릿·인덱스
- 대용량 데이터·모델·비밀정보 제외 규칙

## 비범위

- Google Calendar 동기화
- 실제 개인 일정·아이디어 예제
- 실제 연구 데이터·실험 결과
- Colab·RunPod·GPU 설정
- 자동 실험 평가와 주장 검증
- 사용자 요청 없는 선제 구현

## 완료 조건

- [ ] 실제 사용자 요구가 문서화됐다.
- [ ] 요청된 모듈만 구현됐다.
- [ ] 사용하지 않는 모듈은 빈 상태로 유지된다.
- [ ] 샘플 데이터는 전부 가상 데이터다.
- [ ] 기본 Tier 0 읽기 비용이 증가하지 않는다.
- [ ] 생성기·lint 추가 여부가 Spec에서 결정됐다.

## 진행 메모

사용자가 한쪽 기능만 요청하면 요청된 모듈만 구현하고 나머지는 비워 둔다.
